# الإجراء المخزن `SP_ADD_NEW_USER`

<div dir="rtl">
## معلومات الإجراء

| الخاصية | القيمة |
|---|---|
| الاسم | `SP_ADD_NEW_USER` |
| قاعدة البيانات والمخطط | `[Gilgamesh.v2].[dbo]` |
| الغرض | إنشاء سجل شخص وحساب مستخدم مرتبط به ضمن معاملة واحدة |

## المدخلات

| المعامل | النوع في الإجراء | الوصف |
|---|---|---|
| `@Public_ID` | `CHAR(10)` | المعرف العام للشخص |
| `@FullName` | `NVARCHAR(100)` | الاسم الكامل |
| `@Gender` | `VARCHAR(10)` | الجنس؛ يخضع لقواعد جدول `Persons` |
| `@DateOfBirth` | `DATETIME2` | تاريخ الميلاد |
| `@UserName` | `NVARCHAR(100)` | اسم المستخدم |
| `@Avatar` | `NVARCHAR(300)` | رابط الصورة أو مسارها |
| `@Bio` | `NVARCHAR(250)` | نبذة المستخدم |
| `@Email` | `NVARCHAR(100)` | البريد الإلكتروني |
| `@PasswordHash` | `VARCHAR(256)` | قيمة تجزئة كلمة المرور |

## التحقق من المدخلات والأخطاء

| رقم الخطأ | الرسالة الصادرة | سبب الخطأ |
|---:|---|---|
| `50001` | `Email already exists` | البريد الإلكتروني مستخدم مسبقاً |
| `50002` | `Email Invalid Format` | البريد لا يطابق النمط البسيط الذي يفحصه الإجراء (`%@%.%`) |
| `50003` | `UserName already exists` | اسم المستخدم مستخدم مسبقاً |

يتحقق الإجراء من البريد المكرر، ثم من نمط البريد، ثم من اسم المستخدم المكرر. فحص النمط لا يمثل تحققاً شاملاً من جميع صيغ عناوين البريد الإلكتروني. كما قد ترفض قيود الجداول قيماً أخرى غير هذه الحالات الثلاث.

## سير التنفيذ

1. تعطيل رسائل عدد الصفوف بواسطة `SET NOCOUNT ON`.
2. بدء معاملة قاعدة بيانات.
3. التحقق من البريد واسم المستخدم وفق الترتيب الموضح أعلاه.
4. إضافة سجل إلى `Persons`، ثم الحصول على `Person_ID` المولّد باستخدام `SCOPE_IDENTITY()`.
5. إضافة الحساب إلى `Users` وربطه بمعرف الشخص. لا يمرر الإجراء `UserRule` أو `EmailVerifiedAt`؛ لذا تُطبق القيمة الافتراضية للدور ويظل تاريخ التحقق فارغاً وفق تعريف الجدول.
6. إعادة بيانات الشخص والحساب المحددة أدناه.
7. اعتماد المعاملة عند النجاح. عند وقوع خطأ، يتراجع الإجراء عن المعاملة ثم يعيد الخطأ الأصلي باستخدام `THROW`.

## بيانات النتيجة

يعيد الإجراء صفاً يتضمن الأعمدة التالية: `Public_ID`، `FullName`، `Gender`، `DateOfBirth`، `UserName`، `Avatar`، `Bio`، `Email`. لا يعيد `PasswordHash` أو معرفي `Person_ID` و`User_ID`.

## ملاحظات

- يجب أن تتوافق قيود التفرد في قاعدة البيانات مع فحوصات التكرار؛ إذ لا تمنع فحوصات `IF EXISTS` وحدها تعارض الطلبات المتزامنة.
- تتطلب العملية صلاحية تنفيذ الإجراء وصلاحيات قاعدة البيانات اللازمة للوصول إلى جدولي `Persons` و`Users`.
